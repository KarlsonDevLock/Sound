=====================================================================
 SOUND-TO-BINARY CONVERTER  -  WEB APP STRUCTURE
 (How the app is organized and how data flows through it)
=====================================================================


---------------------------------------------------------------------
 1. THE BIG PICTURE
---------------------------------------------------------------------
The app has NO backend and NO database. Everything runs in the
user's browser, inside ONE file (index.html).

   +-----------+      +-------------------+      +------------+
   |   USER    | ---> |   WEB PAGE        | ---> |   RESULTS  |
   | types 4   |      |  (HTML + CSS +    |      |  shown on  |
   | numbers   |      |   JavaScript)     |      |  the page  |
   +-----------+      +-------------------+      +------------+
      INPUT                 PROCESS                  OUTPUT

It is a classic  INPUT -> PROCESS -> OUTPUT  program.


---------------------------------------------------------------------
 2. THE THREE LAYERS INSIDE index.html
---------------------------------------------------------------------

   +----------------------------------------------------------+
   |  index.html                                              |
   |                                                          |
   |  HTML  = STRUCTURE   (what is on the page)               |
   |           inputs, button, table, text areas              |
   |                                                          |
   |  CSS   = LOOK        (how it appears)                    |
   |           background color, text color, layout           |
   |                                                          |
   |  JS    = BEHAVIOR    (what happens when you click)       |
   |           read inputs, calculate, write results          |
   +----------------------------------------------------------+

 HTML is the skeleton, CSS is the skin, JavaScript is the brain.
 JavaScript finds HTML elements using their  id  names. That is why
 every input and output area needs an id.

---------------------------------------------------------------------
 4. JAVASCRIPT STRUCTURE (THE BRAIN)
---------------------------------------------------------------------
Everything starts when the user clicks CONVERT.

   CLICK on Convert
        |
        v
   +----------------------------+
   | main function (runs once   |
   | per click)                 |
   +----------------------------+
        |
        |-- 1. READ       get the 4 input values, turn text -> numbers
        |
        |-- 2. VALIDATE   are the numbers legal?
        |        |
        |        |-- NO  -> show warning, clear results, STOP
        |        |
        |        '-- YES -> clear warning, continue
        |
        |-- 3. WAVE FACTS compute period + wavelength, show them
        |
        |-- 4. LOOP       for each sample i = 0 ... n-1:
        |        |           compute time
        |        |           compute height
        |        |           compute level
        |        |           compute binary
        |        |           add a row to the table
        |        '--> keep the binary in a list
        |
        '-- 5. SUMMARY    join binaries with spaces, show them,
                          compute and show total bits

 Good practice: split the work into small helper functions, e.g.

   validateInputs()      -> true / false (+ message)
   calcWaveFacts()       -> period, wavelength
   calcSample(i)         -> time, height, level, binary
   toBinary(level, bits) -> padded binary text
   formatWavelength()    -> "1.72 m" or "78.0 cm"
   showResults()         -> writes everything on the page

 Each function does ONE job. The main function just calls them in
 order. This makes bugs much easier to find.

 5. DATA FLOW (WHAT GOES IN, WHAT COMES OUT)
---------------------------------------------------------------------

 INPUTS                        CALCULATIONS                 OUTPUTS
 ------                        ------------                 -------

 frequency ------------------> period = 1/freq x 1000 ----> Period (ms)
     |
     '---------------------->  wavelength = 343/freq -----> Wavelength
                                                             (m or cm)
 amplitude ------------------>  (shown as typed) ---------> Amplitude
 frequency ------------------>  (shown as typed) ---------> Frequency

 samples (n) ---------.
 amplitude -----------+-----> PER-SAMPLE PIPELINE (below)--> Table rows
 bits ---------------'                                  '-> Binary line
                                                         '-> Total bits


---------------------------------------------------------------------
 6. THE PER-SAMPLE PIPELINE (THE HEART OF THE APP)
---------------------------------------------------------------------
For EACH sample i, the data moves through 4 stages:

   i  (position: 0, 1, 2 ... n-1)
    |
    v
 [A] TIME      = i x period / n
    |            "when in the wave are we?"
    v
 [B] HEIGHT    = amplitude x sin(2 x PI x i / n)
    |            "how tall is the wave right now?"  (-1 to +1)
    |            (uses i/n only, NOT the frequency)
    v
 [C] LEVEL     = round( (height + 1) / 2 x (levels - 1) )
    |            "round the height to the nearest whole step"
    |            levels = 2 ^ bits
    v
 [D] BINARY    = level written in base 2, padded with zeros
                 to exactly "bits" digits
                 "the final digital value"


 This is the sound-to-binary idea in 3 words:

     SAMPLE  ->  QUANTIZE  ->  ENCODE
     (A + B)     (C)           (D)


---------------------------------------------------------------------
 7. WORKED TRACE (USING THE "CHECK YOUR WORK" SETTINGS)
---------------------------------------------------------------------
 Input: frequency 1000, amplitude 1, samples 4, bits 2

 Wave facts:
   period     = 1/1000 x 1000      = 1.00 ms
   wavelength = 343/1000 = 0.343 m = 34.3 cm  (less than 1 m -> cm)
   levels     = 2^2 = 4  (levels 0,1,2,3)
   total bits = 4 x 2 = 8

 Per sample:
 +---+------------+----------+-----------------------+-------+--------+
 | i | Time       | Height   | Level calculation     | Level | Binary |
 +---+------------+----------+-----------------------+-------+--------+
 | 0 | 0 x1/4=0.00| sin(0)=0 | (0+1)/2 x 3 = 1.5     | 2 (up)|  10    |
 | 1 | 0.25       | sin(90)=1| (1+1)/2 x 3 = 3       |  3    |  11    |
 | 2 | 0.50       | sin(180)=0| (0+1)/2 x 3 = 1.5    | 2 (up)|  10    |
 | 3 | 0.75       | sin(270)=-1| (-1+1)/2 x 3 = 0    |  0    |  00    |
 +---+------------+----------+-----------------------+-------+--------+

 Binary line:  10 11 10 00        Total bits: 8

 (The table on the page shows Sample # as i + 1, so 1 to 4.)


---------------------------------------------------------------------
 8. WHERE EACH RESULT GOES (JS -> HTML)
---------------------------------------------------------------------
 JavaScript writes results into the empty containers on the page:

   warning message ..........> warning area
   period, wavelength, etc. .> wave facts area
   one <tr> per sample ......> table body   (cleared first each click)
   joined binary string .....> binary line
   n x bits .................> total bits

 IMPORTANT: clear the old results at the start of every click,
 otherwise old rows pile up under the new ones.


---------------------------------------------------------------------
 9. VALIDATION FLOW (THE SAFETY GATE)
---------------------------------------------------------------------

   inputs ---> frequency > 0 ?
                  |  no -> warn, stop
                  v
               0 <= amplitude <= 1 ?
                  |  no -> warn, stop
                  v
               samples is a whole number, 2 to 64 ?
                  |  no -> warn, stop
                  v
               bits is a whole number, 1 to 8 ?
                  |  no -> warn, stop
                  v
               ALL OK -> run the calculations

 The gate sits BEFORE the math, so bad input never reaches the
 formulas and the page never breaks.


---------------------------------------------------------------------
 10. FILE AND HOSTING STRUCTURE
---------------------------------------------------------------------

   YOUR COMPUTER                GITHUB                  THE WEB
   -------------                ------                  -------
   index.html  ---upload--->  repository  ---Pages--->  public link
   (all code                  (public)                  https://user.
    in one file)                                        github.io/repo/

 Anyone opens the link -> their browser downloads index.html ->
 runs it locally. No server code is involved.


---------------------------------------------------------------------
 11. OPTIONAL BONUS STRUCTURE (PLAY BUTTON)
---------------------------------------------------------------------

   click Play -> read frequency -> create audio context
              -> create oscillator at that frequency
              -> start, stop after 1 second

 It is separate from the Convert flow. It only needs the
 frequency input.
